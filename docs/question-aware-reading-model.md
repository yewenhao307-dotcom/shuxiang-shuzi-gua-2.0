# 问题响应式数字卦模型

## 目标

让解读先回应用户的现实问题，再说明卦象为何与该问题相关。模型不重新起卦、不改动卦名、上下卦、动爻、变卦、原文、来源或历法信息。

## 两层架构

### 1. 确定性事实层

由现有程序负责：

- 三组数字与先天八卦映射；
- 本卦、动爻、阴阳变化和变卦；
- 经典原文、来源、卦象文本和纪时信息。

这些字段在解释阶段全部只读。

### 2. 问题响应层

先形成问题画像：

```json
{
  "category": "career",
  "form": "yes_no",
  "time": "现在",
  "action": "离开",
  "object": "这份工作",
  "alternatives": ["离开", "暂时留下"],
  "concern": "职责、资源、长期消耗与替代路径",
  "evidence_prompt": "问题是一次波动，还是已经持续影响职责、成长或身心状态？"
}
```

问题领域与问法分开判断。领域包括决策、工作、关系、资源、学习、身心与综合；问法包括二选一、是否、如何、时机、结果和开放式。

## 映射职责

- 本卦：描述当前处境的底层条件；
- 动爻：指出正在变化、容易误判或应当收束的环节；
- 变卦：只作为条件成立后的可能方向；
- 问题画像：决定答案标题、比较维度、具体对象和验证动作。

不得把变卦写成结果预告，也不得替用户、对方或第三方断定内心。

## 输出顺序

1. 直接回应现实取舍；
2. 用一句话映射本卦；
3. 用一句话说明动点；
4. 给出一至三项可观察、可撤回、可验证的行动；
5. 明确继续条件、暂停条件和一个判断问题。

七张卡的标题随领域变化。例如工作问题使用“当前工作位置、职责与环境、变化信号、可争取空间、离开代价、去留路径、验证行动”。

## 语言模型扩展接口

以后接入本地语言模型时，只允许它根据事实层与问题画像重组文字，并输出受约束 JSON。生成结果必须经过以下校验：

- 不得新增或改写卦名、爻位、变卦、日期、概率或来源；
- 不得出现确定性预测、读心或替用户作决定；
- 禁止固定套话和重复段落；
- 每个行动必须可观察、可撤回或可验证；
- 解析失败或事实校验失败时，回退到当前确定性问题响应文本。
